## 겹치는 파일의 선택

| 파일 | 실제 차이 | 사용할 자료 |
| --- | --- | --- |
| `app.py` | 줄바꿈 외에 시스템 프롬프트 일부, UI 이름, 실행 DB 파일명이 다름 | 새 개발은 레포 버전. 과거 실험 해석은 보존한 당시 코드도 함께 참조 |
| `Readme.md` | 레포 버전에 프로젝트 개요, 결과, 역할, 보고서 링크가 추가됨 | 레포 버전. 개인 역할과 증거 범위 정비는 후속 작업 |
| `.gitignore` | clone 당시에는 줄바꿈만 다름 | 레포 버전. 이번에 `.local/` 및 `.env.*` 제외를 추가 |
| `Dockerfile` | 줄바꿈만 다름 | 레포 버전 |
| `requirements.txt` | 줄바꿈만 다름 | 레포 버전. 설치·버전 변경은 하지 않음 |
| `checkapikey.py` | 줄바꿈만 다름 | 레포 버전. 실행하지 않음 |
| 보고서 PDF | SHA-256이 같음 | 레포에 있는 파일 |
| 최종 발표 PDF | SHA-256이 같음 | 레포에 있는 파일 |

기존 폴더의 Git 상태에서 파일들이 수정으로 표시되더라도, clone 버전과 비교하면 상당 부분은 CRLF/LF 줄바꿈 차이다. 수정 표시나 파일 크기만으로 더 최신인 코드를 선택하지 않았다.

## app.py의 실질 차이

줄 끝의 CR 차이를 제외한 전체 diff에서 다섯 줄의 변경을 확인했다.

1. 시스템 프롬프트의 캐릭터 서비스 이름을 `Zeta Universe`에서 `AINHA_CHAT_SIMULATOR`로 변경했다.
2. 기밀 유지 문장에서 내부 식별자 예시를 제거했다.
3. 거절 응답 예시를 캐릭터 페르소나를 유지하는 지침으로 변경했다.
4. 실행 DB 파일명을 `zeta_final.db`에서 `ainha_chat_simulator_final.db`로 변경했다.
5. 로그인 화면의 서비스 이름을 변경했다.

메모리 추출·저장·조회·응답 생성 함수에는 코드 차이가 없다. 다만 시스템 프롬프트는 동일하지 않으므로, 과거 모델 응답을 현재 레포 버전의 방어 성능으로 그대로 주장하지 않는다. 새 실험에서는 코드 커밋, 실제 프롬프트, 모델·설정과 실행 시점을 함께 기록해야 한다.

## 로컬에만 있던 자료

공개하기 전 검토가 필요한 자료는 `.local/legacy-evidence/`에 복사한다. 이 디렉토리는 `.gitignore`로 제외한다.

- `app.py.snapshot`: 과거 실험 당시 코드의 복사본. 실행 기준 코드가 아니다.
- `attack_report_final.md`, `attack_results.md`: 당시 결과와 판정 기록.
- `plan.md`, `attack_table.png`, 최종 발표 PPTX: 당시 계획 및 원본 편집 자료.
- `.playwright-mcp/`: 당시 브라우저 상태 및 콘솔 로그.
- `zeta_final.db`, `zeta_data.db`: 보존 DB. 분석할 때는 읽기 전용으로 사용한다.

세부 SHA-256 비교 기록과 로컬 원본 위치는 Git에서 제외한 `.local/source-comparison.json`에 기록한다.

기존 `.env`, ngrok 실행 파일, 캐시와 개인 도구 설정은 복사하지 않는다. 새 레포에서 앱을 실행하지 않았으며 새 실행 DB도 생성하지 않았다. 후속 실험의 실행 DB는 보존 DB와 분리해야 한다.

## 증거 해석의 경계

- V4는 장기기억 테이블에 명령문을 직접 넣은 실험이다. V8의 사용자 입력 기반 추출 공격과 주입 경로가 다르다.
- V8의 4/4는 당시 보고서의 판정이다. 현재 보존 자료에서 같은 사례의 함수 응답과 DB 행을 확인하지 못했다.
- 악성 메모리를 생성하거나 저장했다는 사실만으로 최종 응답 우회에 성공했다고 쓰지 않는다.
- 제안한 대응과 실제 적용·검증한 대응을 구분한다.
- 공개 파일 목록에 비밀파일이 없다는 사실은 과거 Git 이력이나 PDF까지 안전하다는 검증이 아니다. push 전 별도 공개 자료 점검이 필요하다.
